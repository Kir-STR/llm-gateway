# Глоссарий — конвенции терминологии

Языковая дисциплина для **содержания** правил, документации, README, описаний issue/PR. Основной язык документации — русский. **Имена** (slug'и веток, имена файлов, импорты, ключи YAML/JSON, идентификаторы кода) — отдельная политика, всегда ASCII.

Цель — снять word-level code-switching в русском тексте, сохранив компактность там, где английский плотнее по смыслу.

## Whitelist — English-OK внутри основного текста

1. **Идентификаторы** — хеши коммитов, пути файлов, имена команд и флагов, имена функций/переменных/классов, ID issue/PR, имена workflow / job / step CI. Сюда же поля контракта ядра: `outcome`, `route`, `transform`, `flags`, `evidence`, enum-значения (`PASS` / `DEGRADE` / `REJECT`), ключи событий телеметрии (`turn_started`, `guard_result`, …).
2. **Proper nouns инструментов** — названия конкретных инструментов, платформ, библиотек (GitHub, pnpm, TypeScript, ajv, vitest, Langfuse и т.п.).
3. **CLI-команды в обратных кавычках** — `git rebase`, `pnpm run lint` и т.п. (как команды/действия, не как глаголы).

## Применение

- В документации берём русский вариант из таблицы переводов ниже. Если перевод неоднозначен на месте — допустимо в скобках продублировать английский.
- Тривиальные когнаты (`session`, `host` и т.п.) в таблицу не вносим — их покрывает дефолт «берём русский вариант»; таблица несёт только неочевидные переводы и keep-English решения.
- Whitelist английских классов и keep-English список не переводим даже при наличии эквивалента.
- Имена (slug'и веток, ASCII-файлы, импорты, ключи) — латиница.
