# Architectural invariants — инварианты проекта

Операционная выжимка по архитектурным границам `@kir-str/llm-gateway`: что где лежит и что куда импортировать нельзя. Источник правды — утверждённая design-спека этапа 1 (`docs/superpowers/specs/2026-07-03-llm-gateway-design.md`). Описывает **целевое** состояние; реальное читается из исходного кода. При переименовании / добавлении модулей — обновлять и здесь.

## Границы слоёв / модулей

Монорепо pnpm; ядро — пакет `packages/gateway`.

- `packages/gateway/src/core/` — оркестрация хода и стадии пайплайна (gateway-фасад, guards-runner, aggregate, router, retry, structured, delivery, config-schema, telemetry, templates, pattern-engine). **Рантайм-агностично: не импортирует `node:*`**, работает в Node 22+, браузере, edge.
- `packages/gateway/src/guards/` — встроенные гварды (normalize пре-стадия, injection, pii, limits). Реализуют контракт `Guard`; доменных строк не содержат — паттерны, пороги, тексты приходят конфигом.
- `packages/gateway/src/node/` — Node-специфика (файловый конфиг-лоадер, JSONL-sink телеметрии, файловое хранилище лимитов). Единственная зона, где разрешён `node:*`; доступна только через entry point `./node`.
- `examples/*` — примеры-потребители; `packages/entitlements` зарезервирован workspace-глобом, каталог не создаётся. Оба — вне ядра.

Инвариант: пакет не знает домена проекта — всё доменное (паттерны, пороги, тексты заглушек, тиры моделей, correction-промпты) приходит конфигом, валидируемым ajv-схемой при инициализации.

## Тонкий публичный фасад

- Публичный API — фасад-оркестратор: `createGateway(config, deps)` → `gateway.runTurn(...)`. В фасаде живут только сборка стадий, оркестрация потока, сквозной `traceId` и эмиссия телеметрии. Бизнес-правила гвардов, retry-логика, парсинг структурного вывода — в стадиях `core/`, не в фасаде.
- Стадии пайплайна — внутренние модули, наружу не экспортируются (обратимое решение: экспорт можно добавить позже без ломки API).
- `createGateway` — единственное место, бросающее исключения (невалидный конфиг / зависимости; «падение сразу и громко»). `runTurn` штатные отказы не бросает — возвращает `outcome: 'rejected' | 'failed'` с текстом-шаблоном.

## Изоляция внешних адаптеров

- LLM — только за интерфейсом `LlmCaller`; SDK провайдеров (`@anthropic-ai/sdk` и др.) **не в runtime-зависимостях** пакета, адаптер поставляется отдельным опциональным entry point.
- Адаптеры (`LlmCaller`, `TelemetrySink`, `LimitsStore`, `node/`-sinks) друг друга не импортируют; координация — уровнем выше (фасад / `core/`), не в адаптерах.
- Ядро зависит от абстракций (интерфейсы публичных типов), не от конкретных реализаций; реализации приходят через `deps` в `createGateway`.

## Общие модули — без бизнес-логики

- Публичный тип-контракт ядра (`Verdict`, `Guard`, `TurnContext`, `LlmCaller`, `TelemetrySink`, `LimitsStore`, `GatewayConfig`, типы telemetry-событий) — типы, enum'ы, интерфейсы; без stateful-классов и доменной логики.
- В `evidence` и телеметрию никогда не попадают немаскированные ПД и секреты — см. [[secret-hygiene]].

## Доверенный контекст vs недоверенный ввод (security-инвариант)

Изоляция scope доступа к данным — структурная, а не эвристика: у модели нет канала, через который она могла бы выбрать scope.

- `TurnContext.meta` — **доверенный серверный контекст** (сессия, auth; `Readonly`). `input`, `output`, `structured` — **недоверенные, под влиянием модели**.
- Ядро **не прокидывает `meta` в `LlmRequest`**: встроенный llm-сценарий шлёт модели только текст хода и настройки модели. У `LlmRequest` **нет и не должно появляться** поля сессии/скоупа/тенанта — само это отсутствие и есть гарантия. Регресс-тест: `packages/gateway/tests/trusted-context.test.ts`.
- Scope/auth-идентификаторы берутся только из `meta` (лучше — захвачены в серверном замыкании `LlmCaller`/RAG), **никогда** не извлекаются из диалога или `structured`-вывода модели.
- Граница гарантии: фреймворк держит `meta` вне встроенного `LlmRequest`; он не полицирует, что делают кастомный `ScenarioHandler` или проектная реализация `LlmCaller` с данными, которыми владеют сами. Enforcement доступа к данным/тулам — auth-слой / будущий `packages/entitlements`. См. [[secret-hygiene]].
- Threat model: prompt injection → cross-tenant/cross-section доступ. Этап 2+: server-bound scope enforcement (все запросы к данным/тулам получают scope из серверной сессии; tool-слой, если появится, перетирает scope, пришедший от модели).

## Конвенции импортов / зоны

- TypeScript strict, module NodeNext, target ES2022, ESM.
- Две зоны: рантайм-агностичная (`core/`, `guards/`, entry `.`) — `node:*` **запрещён**; Node-зона (`node/`, entry `./node`) — `node:*` **разрешён**. Новый файл следует конвенции соседей по каталогу, а не вводит свою.
- Runtime-зависимости ядра: `ajv`, `ajv-formats`; `yaml` — только в `./node`. Зависимостей сверх согласованного списка не добавлять без явного решения — см. [[versioning]] по контрактам.
